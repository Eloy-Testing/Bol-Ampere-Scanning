# Standalone Vercel Scanner Implementation Plan

- **S1 — user_request:** Remove CoWork artifact metadata, MCP identifiers, and the `window.cowork` bridge; replace them with same-origin session/state/retailer/scan HTTP clients while preserving the proven FIFO scanner loop.
- **S2 — user_request:** Add an idempotent Turso/libSQL migration and repository for isolated `ampere_*` station/principal/session audit records, shared login lockout, current workday package state, append-only scan events, and an atomic write-batch decision that prevents cross-station double completion without storing full bol payloads or coupling to existing Bankhoes tables.
- **S3 — required_dependency:** Add standalone Node.js Vercel Functions and shared server modules for scrypt password verification, signed opaque audited sessions, route/origin enforcement, strict validation, bol OAuth token caching, four read-only Retailer API shapes, server-authoritative scan verification, bounded timeouts, safe error mapping, and production security headers.
- **S4 — required_dependency:** Add a focused login/session-expiry/shared-state-failure surface that collects constrained audit labels, fails closed, never persists credentials or operational state in browser storage, hydrates Turso workday state, and hands focus to the scanner only after auth, database, and bol snapshots are healthy.
- **S5 — required_dependency:** Add deployment and migration configuration plus operator documentation for the existing Turso environment contract, password-hash generation, idempotent migration, credential rotation, and account-boundary Vercel steps without copying or committing live secrets.
- **S6 — required_dependency:** Replace the CoWork synthetic bridge with same-origin HTTP fixtures; add server/database unit tests and one local end-to-end path through the actual session/state/retailer/scan handlers while retaining all security, pagination, timezone, refresh, shared persistence, queue, duplicate, cancellation, focus, and mobile assertions.
- **S7 — required_dependency:** Validate the contracts and Vercel-shaped project, run the migration against a disposable local libSQL file, run the full suite, apply/verify only the approved additive `ampere_*` migration against the named Turso database after local proof, inspect current desktop/mobile login and ready/scan states, record visual/state evidence, and pass the project-local adoption gate.

## Immutable finish line

The repository runs as a standalone static frontend plus its own authenticated Vercel Functions and isolated shared Turso state, contains no CoWork/MCP runtime dependency, browser-only operational state, browser-side secret, or dependency on Bankhoes application code/tables, preserves the rapid fail-closed `start → scan → next → repeat` flow across stations, and is locally plus schema-verified without accessing a live bol or Vercel account.
